# Contour

*See the shape of your growth.*

Contour is a full-featured SaaS analytics dashboard built from scratch in **vanilla JavaScript, HTML, and CSS** — no framework, no build step, no external dependencies. It's a static site: open it behind any web server and it runs.

## Features

- **Overview** — headline KPI cards (Revenue, Active Customers, Conversion Rate, Traffic) with trend badges and sparklines, a live analytics chart, a recent-activity feed, and a "customers needing attention" list
- **Analytics** — a hand-rolled SVG line/area chart with a metric switcher and date-range selector, hover/keyboard tooltips, and an always-present accessible data table
- **Customers / Transactions** — a shared, reusable data-table engine: search, status filtering, sortable columns, pagination, and CSV export of exactly what's currently filtered
- **Customer detail drawer** — full account info and transaction history, opened from any customer row
- **Reports** — live snapshots that reuse whatever's currently selected elsewhere in the app (current metric/range, current table filters) rather than a separate dataset, each with its own CSV export
- **Settings** — editable profile (persisted locally), a genuine three-way theme mode (light/dark/system, including live OS-theme updates), and notification preferences that actually affect the UI
- **Light/dark/system theming** throughout, built on CSS custom properties
- **Fully responsive**, tested at 320px through 1440px+
- **Accessible by construction** — semantic HTML, ARIA states (`aria-sort`, `aria-current`, `aria-pressed`, `aria-expanded`), keyboard operability, managed focus (including a full drawer focus trap), and status/trend information that's never color-only

## Tech stack

Nothing but the browser platform:

- Vanilla JavaScript (ES modules), no framework
- Vanilla CSS with a design-token system (`css/tokens.css`) — colors, type, spacing, radius, motion
- Hand-rolled SVG for every chart and sparkline
- A small centralized state store (`js/state.js`) with a subscribe/notify pattern — no virtual DOM
- Static JSON as the data layer, loaded via `fetch()`
- Zero npm dependencies, zero build tooling, zero CDN assets

## Getting started

The app fetches its data as JSON, so it needs to be served over HTTP — opening `index.html` directly (`file://`) won't work.

```bash
cd contour-dashboard
python -m http.server 5505
```

Then open `http://localhost:5505`. Any other static file server works just as well.

## Project structure

```
contour-dashboard/
├── index.html
├── css/
│   ├── tokens.css        # design tokens: color, type, spacing, radius, motion
│   ├── base.css          # reset + global rules (focus, reduced motion, a11y)
│   ├── layout.css        # app shell layout
│   └── components/       # one file per UI component
├── js/
│   ├── app.js             # bootstrap: theme, data load, shell, router
│   ├── router.js          # hash-based SPA router
│   ├── state.js           # centralized state store
│   ├── theme.js           # theme detection/persistence (light/dark/system)
│   ├── views/              # one file per route (Overview, Analytics, ...)
│   ├── modules/            # reusable pieces (chart, table engine, drawer, ...)
│   └── utils/               # pure helpers (formatting, CSV export, focus mgmt)
├── data/                  # generated mock JSON (kpis, timeseries, customers, ...)
└── scripts/
    ├── generate-data.js    # deterministic (seeded) mock-data generator
    └── verify-data.js      # independently re-derives and cross-checks the data
```

## Data

All data is generated by a seeded, deterministic script (`scripts/generate-data.js`), so it's reproducible. `scripts/verify-data.js` independently re-derives figures from the shipped JSON and cross-checks them against what the files claim — run it any time with:

```bash
node scripts/verify-data.js
```

## Quality

Built milestone by milestone (data/foundation → layout/nav → KPIs → analytics chart → tables/drawer/activity → reports/settings/export), then hardened with a full release audit covering responsiveness, accessibility, interaction/state correctness, data integrity, visual consistency, performance, and code quality — including a fix for a keyboard focus-order bug that made the skip link unreachable, and several other real, verified issues caught before ship.
